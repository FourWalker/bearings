Tack in an open module or task

Today, telling an agent "continue with the task" means pressing Continue in new thread, which leaves the board and opens the whole chat screen for one sentence. In this concept Tack sits inside the open module or task and is that button: a box that is there the moment the task opens, takes a quick question or a "continue", and grows only when the conversation needs room. Every chat is still a real thread on the task. Concept only, nothing here is built.

    2 · One chat, three sizes, and the full thread one click away

    The size is yours to set and Tack never resizes itself. When a reply is long it only marks the next size up, as in the "clarification" scene. Each board remembers the size you last used in a task.

    Line default

    One row at the foot of the task.
    • For "continue", "status?", a one-line question.
    • The answer shows in a small card above the row, then folds to a one-line status.
    • While a thread works, the row is its live status with Stop.

    Panel

    A column beside the task.
    • For a back-and-forth while you read the plan or the handoff.
    • Shows the recap and the latest exchange, earlier messages on request.
    • Opens by itself only when a thread on this task waits for your answer.

    Wide

    The chat takes the room; the task becomes a rail.
    • For detailed clarifications, long replies, code and tables.
    • Plan steps stay visible at the side and tick as work lands.
    • You are still in the task: Esc steps back to Panel.

    Full thread

    The chat screen you have today.
    • Same thread, nothing converted or copied.
    • For diffs, terminals, file review, model and mode settings.
    • Always one click away: "Full ↗" in Tack's header, and the Threads tab.

    3 · What a message does

    One rule: a chat with Tack in a task is a thread on that task. There is nothing to convert later; "turning into a real thread" only means the same thread starts doing work, or you open it full size.

    You doWhat happens
    Open a module or taskTack is there with an empty "New chat". No thread exists yet and nothing is sent or loaded. If a thread on this task is working or waiting for you, Tack shows that thread instead.
    Send in "New chat"A thread is created on this task, in the task's workspace, and put on the task before its first turn, so that turn already carries the plan and the handoff. This is what "Continue in new thread" does today, without leaving the task.
    Send with a thread loadedYour message is that thread's next turn.
    AskTack answers and changes nothing without your approval. A chat that only ever asked is a quick chat.
    Run, or the Continue chipThe agent works on the task. "Continue" sends "Continue this task from its handoff" in one click. A quick chat becomes a work thread the first time you Run in it.
    The agent asks you somethingTack rings. The question or approval shows in place, in any size, with its answers as buttons.
    More than one workspace fitsThe Continue chip opens the same short menu the button has today (workspace, "once", "take over"). With one workspace there is no menu.

    4 · Earlier chats, and what to do when one is long

    The thread list is Tack's ownPress the name next to Tack. "New chat" on top, then threads that are working or waiting, then work threads by date, then quick chats folded into one line so they do not crowd the list. Each row shows state, age, size and the last thing you asked.
    Picking a thread loads it into Tack, in the size you are inThe Threads tab keeps its cards; "Open thread" there becomes "Open here" with "Full" beside it.
    A long thread opens on a recap, not on message 1First a short card: what it was asked last, what it answered, what it did last, and where the plan stands. Under it only the latest exchange. This data is already on the board for every thread.
    Earlier messages come in pages"Show earlier" loads the previous 20. Tack follows the one thread that is loaded, and only while the task is open, so a 140-message thread costs nothing until you ask for it.
    Long thread, new work: offer a fresh startContinuing a very long thread makes every turn carry all of it. When a loaded thread is long, the Continue chip offers "Start fresh from the handoff" beside "Continue here". The handoff exists for exactly this.
    Too much to read in a columnWide gives it the room, and "Full ↗" gives it the whole screen. Tack marks the next size up when a reply runs long; it does not jump there.

    5 · Where this shows up

    PlaceWhat Tack is there
    Module or task (the dialog)As in the mock above. Replaces "Tack waits behind the dialog", which is how it works now.
    Feature task (the page)The same Tack in the same three sizes, in place of the floating "Ask Tack" pill. Its thread list groups threads by module.
    The boardUnchanged: Tack lives on the board and answers about the whole board from its own thread. Later: when Tack stands on a note, its bubble gets a Continue chip, so "continue" needs no open task at all.
    Narrow windowLine stays a row. Panel becomes a sheet over the lower half. Wide covers the task with a back arrow.
    Threads tab"Continue in new thread" stays as "Continue in full chat" for when you want the big screen from the start.

    7 · Build order

    1. Line and Panel in the module/task dialog. New chat, send, the Continue chip, live status and Stop, approvals in place, "Full ↗" to the chat screen. Reuses Tack's message list and box, and the same thread creation the Continue button uses.
    2. The thread list and long threads. Tack's list, loading a thread, the recap card, earlier messages in pages, the fresh-start offer.
    3. Wide, and the Feature page. The task rail, remembered size, the page's Tack in place of the floating pill.
    4. Later. Continue from a note's bubble on the board; narrow-window sheet; mobile.
